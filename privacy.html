Burka Personal Orchestrator

Privacy notice

Burka is an experimental assistant maintained by VlaSiv for personal project planning, discussions, and open questions. This notice describes the current local installation and its Google connector.

The application is used by its owner, with two explicitly authorized Google accounts. The information website does not offer public access to the assistant.

Google access and purpose

Each account is connected separately through Google's OAuth consent flow. Burka stores authorization and account-identification information to reconnect and check that it is reading the intended account. It does not receive the account's Google password.

The connector uses Google's REST APIs to perform reads requested for the owner's tasks:

  • Calendar: read events from the primary calendar for a selected time range, and calendar identity metadata.
  • Gmail: search message identifiers, read a selected message's headers and content, and check account identity. There is no separate attachment-download feature.
  • Drive: search files and return metadata, including names, types, modification times, links, and descriptions. The granted read-only permission is broader than the current metadata search; file-content download and export are not implemented.

These results can help answer a question, prepare a summary, or relate requested information to a project. The connector has no email-send, calendar-edit, file-upload, or Google-data deletion feature.

External AI services

When the owner asks Burka to use Google information in an AI-assisted task, selected results may be included in requests to the configured OpenAI service. When the owner requests an independent review, a selected review brief may also be sent through GitHub Copilot. The current Copilot reviewer receives the brief, without direct access to the Google accounts.

Information sent to an AI provider is processed outside the local device under that provider's terms and the account's data controls. Provider retention periods and deletion procedures remain subject to those terms and controls; this notice does not promise zero retention. The owner's confirmed restrictions on model training are described below.

Google credentials are used by the local connector to call Google; they are not intended to be included in model prompts, review briefs, or public website content.

Storage and retention

Google OAuth credentials and account metadata are stored in the owner's local operating-system profile, protected by filesystem access permissions. The Google connector does not add application-level encryption to its token files. This notice makes no claim that device or disk encryption has been verified.

Selected information and generated answers may remain in local Hermes conversation history, saved artifacts, summaries, and owner-managed backup copies. There is no automatic retention deadline configured for this material. It remains until the owner deletes the relevant records and copies.

The information website does not host the application's credentials, conversations, Google results, or operational database.

Revocation and deletion

The owner can revoke Burka's Google authorization through Google Account connections. Each connected Google account has its own authorization to manage.

Revoking authorization does not erase information already retrieved. To remove local copies, the owner must delete the relevant conversation records, artifacts, summaries, exported material, and backup copies. Removing the local credential files is a separate action from removing saved content.

Copies already submitted to an external service are subject to that service's retention rules and deletion controls. Deleting a local conversation is not a request to delete a provider's copy.

Data use and training

Burka has no model-training pipeline. Its operator does not sell Google user data, use it for advertising, or train its own models with it.

Google Workspace API data, including information derived from it, is not used to develop, improve, or train generalized or non-personalized artificial-intelligence or machine-learning models. This restriction also applies to transfers to external AI services.

Burka uses only owner-approved AI services configured to exclude Google-derived information from generalized model training. The owner confirmed this configuration for the OpenAI/ChatGPT and GitHub Copilot accounts used by Burka on 28 October 2026. This is an owner attestation, not an independent provider audit.

Burka commits to using and transferring information received from Google APIs in accordance with the Google API Services User Data Policy, including its Limited Use requirements. This includes the restrictions described in Google's privacy requirements for AI use.

Website hosting

These pages contain no JavaScript, forms, analytics, advertising, third-party fonts, or external assets. The site code does not set cookies or use browser storage.

This information site is hosted on GitHub Pages. GitHub handles website requests and logs visitors' IP addresses for security purposes. Other technical request data is handled under the GitHub Privacy Statement. The absence of site analytics does not mean the hosting service receives no request data.

Contact and changes

The maintainer is VlaSiv. Use the project's GitHub issues for general questions. Issues are public: do not include Google account addresses, private messages, document contents, tokens, or credentials.

This notice should be updated before a material change to the data sources, sharing, storage, or purpose described here. Any new Google access requires the appropriate authorization.
